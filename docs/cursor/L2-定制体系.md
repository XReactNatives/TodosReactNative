# L2 · 定制体系（七组件全落地）

知识点来源：《Cursor 核心知识》二~六、《方法论》方法2/3、《最佳实践》Rules vs Skills。
核心分工：**Rules 管常识（每次带），Skills 管能力（相关才加载），Commands 管快捷工作流，Subagents 管并行隔离，Hooks 管生命周期边界，MCP 管外部工具，Plugins 管打包分发。**

## Rules（静态常识，按 glob 触发）

| 文件 | glob | 命中知识点 |
|---|---|---|
| `AGENTS.md` | 根目录纯 md | 核心知识§二「AGENTS.md 纯 markdown 替代」 |
| `00-architecture-layers.mdc` | `src/**` | 本项目 `architecture.md` 四层单向依赖 → Rule 化 |
| `10-state-redux.mdc` | `src/state/**` | RTK thunk/slice/selector 规范 |
| `20-presentation-rn.mdc` | `src/presentation/**` | RN 最佳实践·性能（memo/useCallback/createSelector/keyExtractor）|
| `30-typescript.mdc` | `src/**/*.{ts,tsx}` | RN 最佳实践·类型（禁 any、边界校验）|
| `40-service-api.mdc` | `src/service/**` | 服务层单一职责 |

设计要点：每条 < 50 行、一个关注点、含正反例；纯 md 用 `AGENTS.md` 而非放进 `.cursor/rules`。

## Skills（动态能力，`.cursor/skills/`）

| 技能 | 触发 | 作用 |
|---|---|---|
| `add-feature-slice` | "新增功能/加 CRUD/vertical slice" | 按四层顺序生成完整纵切；SKILL.md<500 行，模板下沉 `reference.md`，锚点插入下沉 `scripts/` |
| `layer-audit` | "审查架构/检查分层" | 只读输出违规报告 |
| `redux-slice` | "加一个 slice/新 redux 状态" | 只生成状态层三件套 |

设计要点：`description` 三人称 + WHAT + WHEN + 触发词；渐进式披露（主干+引用文件+脚本）。

## Commands（`/` 触发）

`verify`（lint+tsc+jest 质量门）、`run-ios`、`run-android`、`bundle-split`（复用现有分包脚本）、`new-slice`（触发技能）。

## Subagents（独立上下文）

`layer-guardian`（架构守卫）、`perf-reviewer`（过渡渲染/列表性能）——均只读、只报告。

## Hooks（生命周期边界，进仓库）

- `beforeShellExecution` → `guard-shell.js`：拦截 `rm -rf`/force push/删原生工程。
- `afterFileEdit` → `format-edited.js`：对改动的 `src/**/*.{ts,tsx}` 跑 prettier + eslint --fix。

## MCP（外部工具，token 占位）

`.cursor/mcp.json` 配 `github`（管 PR/issue）与 `filesystem`；秘钥走 `${GITHUB_PERSONAL_ACCESS_TOKEN}` env，见 `.env.example`。传输用 `stdio` + `env` 传密。

## Plugins（打包分发）

`.cursor-plugin/plugin.json`（清单只强制 `name`）+ `README.md` 说明本地测试与发布。衔接 L4 团队分发。
