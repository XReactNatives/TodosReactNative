# L1 · 交互内核（按任务大小选入口）

知识点来源：《Cursor 核心知识》一、《方法论》方法1、《最佳实践》交互与工作流。
核心：**为任务规模选对表面**，而不是什么都丢给 Agent。

## 入口 × 本项目真实任务

| 入口 | 适用 | TodosReactNative 示例 |
|---|---|---|
| Tab | 顺手补全 | 在 `todosSlice.ts` 写 `.addCase(` 时补全生命周期 |
| Cmd+K | 单点/局部外科式编辑 | 选中 `TodoItem` 的 `styles.deleteButton` 改配色 |
| Ask | 只理解、不改 | "解释 `addTodoAsync` 从 dispatch 到 slice 的生命周期" |
| Agent | 多文件特性/重构 | 新增"编辑 Todo"纵切（service→domain→state→presentation）|
| Plan Mode（Shift+Tab）| 任何 >1 文件的任务 | 新增一条导航路由 + 页面前，先出方案再执行 |

## 决策流程

1. 只想问/理解 → **Ask**
2. 改一处、范围明确 → **Cmd+K**
3. 顺手补全 → **Tab**
4. 多文件/新特性 → 先 **Plan Mode** 出方案，批准后切 **Agent**
5. 任务很大 → 拆成多个顺序会话，别一个巨型 prompt

## 本项目落地建议

- 新增功能纵切属于"多文件特性"：先 Plan Mode，再让 Agent 调用 `add-feature-slice` 技能。
- 始终读 diff、提交 checkpoint；AI 产出是高质量初稿而非终稿。

检验：动手前能一句话说明"为什么用这个入口"。
