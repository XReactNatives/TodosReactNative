# L4 · 团队治理与分发

知识点来源：《Cursor 方法论》方法10、《最佳实践》安全与治理、Plugins 文档。

## 已具备的治理基础

- `.cursor/rules` 已纳入版本控制（随仓库分发，团队统一）。
- 秘钥不落库：`.env` 已被 `.gitignore` 忽略，只提交 `.env.example`。
- Hooks 作为项目策略边界（危险命令拦截）对所有协作者生效。

## Team Rules 方案

在 Dashboard → Rules 配置 Team Rules，把最关键的一条设为**必需（Required）**：

- 必需：`00-architecture-layers`（四层单向依赖）—— 保证团队不破坏架构底线。
- 建议（Default On）：`10~40` 其余规则。

## Plugin 分发方案

1. 用 `.cursor-plugin/plugin.json`（`todos-rn-toolkit`）打包全部组件。
2. 本地验证：`ln -s "$(pwd)" ~/.cursor/plugins/local/todos-rn-toolkit` → Reload Window。
3. 团队分发：Dashboard → Plugins → Team Marketplace「Import from Repo」导入本仓库；设 Marketplace Access 与安装模式：
   - Required：架构规则插件（强制）。
   - Default On：技能/命令工具箱（可选退出）。
4. 开启 Auto Refresh（需 Cursor GitHub App），推送即更新。

## 安全与计费

- 团队自动化用 **Service Account key**（计费归团队），不要用个人 key 跑 CI。
- 开启 Privacy Mode，用 Dashboard 监控模型访问与用量。

检验：新人克隆仓库或装上团队 plugin，即获得一致的 AI 行为与架构约束。
